Notifications: never land on an empty Messages pane

Two live mention rows (#72, #73) were written before notifyMentions() passed its
context through, so they carry link_id 0 AND project_id 0 — no target at all.
targetFor() correctly fell back to nav('messages'), but on mobile that is a blank
pane reading "Select a conversation" with the channel list off-canvas, which is
what Moe screenshotted. Landing somewhere is not the same as landing usefully.

Two changes so this cannot look like a dead click again:

- When a notification has no deep link and belongs on Messages, targetFor() now
  also returns a `view` — the Mentions list for a mention, the Comments feed for
  anything else. Those lists contain the item itself with its text, instead of an
  empty conversation pane.

- renderMessages() opens the conversation list on mobile whenever nothing is
  selected. The list is display:none until .conv-list-mobile-open on narrow
  screens, so an unselected Messages screen previously showed nothing at all and
  gave no hint that the "Channels" button was the way forward.

The two legacy rows are separately repairable and are backfilled by hand: both
bodies match rows in `messages` on channel 7 (System feedback), message ids 16
and 18, so they become link_type 'channel' with a ref_id and deep-link properly.
